# PH CE Workflows

## Overview
This directory contains utilities and workflow definitions specific to the PH installation of Coordinated Entry (CE) workflows.
See [CE Workflow Builders](../../../../../docs/features/hmis/ce-workflow-builders.md) for general documentation on the CE workflow builder pattern.

### Workflow Templates
- **Direct Referral Workflows**:
  - Benefits Referral
  - Shelter Referral
  - Outreach Referral

These 3 referrals have differing first steps, but the workflows are the same after that with a "Provider Decision" and "Create Enrollment" step.

- **Waitlist Referral Workflows**:
  - Housing Workflow
  - High-Impact Workflow (not yet implemented)

### Usage

These workflows expect client-specific forms to be available. The forms can be loaded with `CLIENT=client rails driver:hmis:seed_definitions` or `HmisUtil::JsonForms.new(env_key: 'client', data_source_id: 1).seed_record_form_definitions(roles: [:CE_REFERRAL_STEP])`

### Direct referral workflows

Generated by `CeWorkflows::Ph::WorkflowBuilder` via `rails driver:hmis:ce_define_ph_direct_workflows`.

This uses the non-preferred draft idempotent pattern — see [README_FOR_CE_WORKFLOW_BUILDERS.md](../README_FOR_CE_WORKFLOW_BUILDERS.md) for why this pattern is not used for new workflows.

### Housing workflows

Generated by `CeWorkflows::Ph::HousingWorkflowBuilder` via `rails driver:hmis:ce_define_ph_housing_workflows`.

This follows the AC-style destroy-and-recreate pattern (see [README_FOR_CE_WORKFLOW_BUILDERS.md](../README_FOR_CE_WORKFLOW_BUILDERS.md)): each run deletes the existing `housing_workflow` template and associated referrals, then creates a new published template.

```
rails driver:hmis:ce_define_ph_waitlist_workflow
UNSAFE_RUN_IN_PRODUCTION=true rails driver:hmis:ce_define_ph_waitlist_workflow  # one-time prod setup only
```

The task is blocked in production unless `UNSAFE_RUN_IN_PRODUCTION=true` is set. Re-running in dev/staging is safe for iteration but will destroy existing referrals against the housing workflow.
